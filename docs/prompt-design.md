# Prompt Design

让大模型基于"用户画像 + 候选车型"生成一份针对当前用户的购车决策报告。

## 关键设计决策

### 1. 输出格式：结构化 JSON，而非 Markdown

PRD 原方案是让模型返回 Markdown，应用用 `flutter_markdown` 渲染。实际开发时改成了"模型返回结构化 JSON，套进应用既有的黑白卡片布局"。原因：

- **保留视觉设计**：黑色结论卡 / 星级排序 / ✓ ! 单色分析卡是 App 的核心观感，Markdown 渲染会把它们退化成普通的标题 + 列表。
- **可控、可校验**：JSON 输出可以做严格的字段校验、补齐缺失的候选车型、过滤非法 id。
- **可扩展**：未来要做"对比表格""筛选""分享某辆车的分析"等功能，结构化数据天然方便。

代价是稍微增加了 prompt 复杂度（要求 strict JSON），但 GLM-4 / DeepSeek / 通义都支持 `response_format: json_object`，模型遵循度很高。

### 2. 模型选择：智谱 GLM-4-Flash

- **免费**，且明确标注免费
- **国内直连**，模拟器/真机不需要走代理
- **响应快**（秒级），适合移动端阻塞式调用
- **OpenAI 兼容接口**，切换到 DeepSeek / 通义 / 百度只需改 `baseUrl` + `model`

### 3. 兜底策略（关键）

`LlmConfig.apiKey` 为空或调用失败时，App 自动切换到 `ReportEngine.buildLocalReport()` —— 基于规则的本地报告引擎，产出同样结构的 `AiReport`。

- 报告页底部显式标注「本报告由本地规则引擎生成」
- 顶部展示一条灰色 banner，告知用户当前未使用 AI
- 用户体验不中断，演示稳定

这正好对应 PRD 第十四节的风险条目："LLM API 返回不稳定 → 准备 fallback 文案"。

## Prompt 结构

### System Prompt

> 你是一位资深的新能源汽车选购顾问。你会基于用户的真实情况给出有针对性的购车建议，诚实指出每款车的短板，不做营销话术。

短、明确角色、强调"诚实指出短板"——避免模型变成营销话术机。

### User Prompt 要点

1. **用户画像** —— 5 个字段（场景 / 日均里程 / 充电条件 / 预算 / 最在意）
2. **候选车型** —— 完整 JSON（包括 id、参数、优缺点）
3. **5 条硬性要求**：
   - 结合实际场景，不堆砌参数
   - 评价要有针对性（举例：不能装家充的用户重点看快充）
   - pros / cons 用第二人称（"对你来说…"）
   - 诚实指出短板
   - ranking 必须包含全部候选车型
4. **JSON Schema 模板**

### 输出 Schema

```json
{
  "conclusion": "一句话结论，直接说最推荐哪款车、核心理由",
  "ranking": [
    {
      "car_id": "候选车型的 id",
      "headline": "针对这位用户，这款车的一句话定位",
      "pros": ["对你来说合适的点", "..."],
      "cons": ["你需要注意的点", "..."]
    }
  ],
  "final_advice": "2-3 句最终建议"
}
```

`ranking` 顺序即推荐优先级（index 0 = 最推荐）。`car_id` 必须来自候选车型列表。

## 解析与防御

`LlmService._parseReport` 做了三层防御：

1. **提取 JSON**：先尝试 `jsonDecode(content)`；失败则定位首个 `{` 与最后一个 `}`，对中间内容再解析。
2. **过滤非法 id**：模型偶尔会编造 car_id，过滤掉。
3. **补齐缺失车型**：若 ranking 漏掉了任一候选车型，用本地数据补齐到末尾（headline 留空 + 默认 pros/cons）。

`ranking` 为空抛 `FormatException`，由 `LoadingScreen` 兜底到本地引擎。

## 未来改进方向

- **流式输出**：边接收边渲染，加载页不再是静态 spinner
- **few-shot 示例**：在 user prompt 里附 1-2 个完整示例，提升小模型表现
- **数据时效性**：接入懂车帝/汽车之家 API 替换本地 `cars.json`
- **多轮交互**：让模型反问场景细节，画像更精准
- **A/B 评估**：搭一个 prompt 评测框架，量化"诚实度""针对性"
